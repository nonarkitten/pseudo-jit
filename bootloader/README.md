# The Buffee bootloader

The bootloader is the first program that runs on a Buffee board. It lives in the board's SPI flash, is loaded by the AM335x's boot ROM into 127 KB of on-chip RAM, brings the hardware up,
and then loads and starts PJIT. It is about 45 KB and has no operating system; it is plain C and ARM assembly written for the Cortex-A8. What it does, in order, is described in
[../docs/buffee/BOOT_SEQUENCE.md](../docs/buffee/BOOT_SEQUENCE.md); the signals it sets up are in [../docs/buffee/BUS_INTERFACE.md](../docs/buffee/BUS_INTERFACE.md).

## What is in it

| directory | holds |
|---|---|
| `src/` | `main.c` (the boot sequence), `post.c` (the self-test), `busclock.c` (the Amiga's bus clock, the host it identifies, the E clock), `payload.c` (loading, staging and starting PJIT), `menu.c` and `settings.c` (the menu and its settings page), `console.c` (reading what is typed), `store.c` (flash slots with CRC), `xmodem.c` (receive an image over the UART), `writeimage.c` (update the bootloader in the flash) |
| `hal/` | the hardware, one file per block: clocks and PLLs (`clocks.c`), DDR (`ddr_emif.c`), the PMIC (`power.c`), the GPMC and the clock-phase calibration (`gpmc.c`), the bootloader's own accesses to the Amiga's bus with or without the byte swapper (`amiga.c`), the GreenPAK (`gpak.c`), the PRU (`pruss.c`), I2C (`i2c0.c`), SPI flash (`flash.c`), the settings in the EEPROM (`config.c`), GPIO and interrupts (`gpio.c`, `irq.c`), the MMU (`mmu.c`), the UART (`uart.c`), a timer (`dmtimer.c`) |
| `pru/` | the firmware of the PRU that echoes the bus clock and makes the E clock (`main_gp4.c`; the compiled form is checked in as `src/pru_text.c` and `pru_data.c`) |
| `greenpak/` | the GreenPAK design (`buffee.gp6`, the exports `buffee4.hex`) and the register images the bootloader writes into it at every boot (`asn_image.h`, one for boards with the byte swapper and one without, generated by `tools/buffee/gen_asn_image.py`) |
| `clib/` | start-up code (`init.s`), `printf`, a few string and memory functions, divide helpers |
| `inc/`, `shim/` | headers: the settings structure (`config.h`), register definitions (`am335x_regs.h`), stand-ins for the system headers the cross compiler does not have |
| `linker.lds`, `makefile` | the link script (everything in on-chip RAM) and the build |

## The boot and the menu

At power-on the bootloader runs its self-test and starts PJIT from the flash ([the boot sequence](../docs/buffee/BOOT_SEQUENCE.md)). The first boot after the settings were reset
runs the full test (all of the DDR) and prints a report; once one passes, later boots run the short test and print a single line. ESC pressed at any time before PJIT starts
stops at the menu instead, and so does a failed self-test or a missing PJIT bundle. Three ESC in a row stop PJIT or a long operation and return to the menu.

The menu is numbered, and 0 goes back:

```
 1. Boot PJIT from the flash
 2. Run a PJIT bundle sent over XMODEM (not stored)
 3. Flash images        the PJIT bundle and the ROM image: store (XMODEM, or a copy of the Amiga's ROM), erase; update the bootloader
 4. Settings            MapROM, fast RAM, pace, bus and ARM clocks, the boot report and the self-test; leaving offers to save them in the EEPROM
 5. Diagnostics         a summary of the board, the full DDR test, a first boot next time, read and write memory
 0. Reboot
```

## Building

`make bootloader` from the repository root builds it (`BL=asn_cal` adds a printout of the clock-phase calibration); `make firmware` builds it together with the Kickstart bundle. The
output is `build/bootloader/asn/bootloader.bin`. The bootloader embeds its build time, so two builds of the same source differ in a few bytes. [../docs/getting-started.md](../docs/getting-started.md)
puts it on a board.

## Connecting to the board

The board has two Tag-Connect footprints (TC2030 for the UART and I2C, TC2050 for JTAG). Pin-outs, seen from the connector side:

```
 UART / I2C (TC2030)                        JTAG (TC2050)
          _                                          _
         (_)   Alignment pin (GND)                  (_)   Alignment pin (GND)

3.3VDC   o o   I2C SCL                     3.3VDC   o o   Reset
FTDI Rx  o o   FTDI Tx                     TMS      o o   TRST
GND      o o   I2C SDA                     GND      o o   TDI
        _   _                              TCK      o o   GND
       (_) (_) Alignment pins (GND)        GND      o o   TDO
                                                   _   _
                                                  (_) (_) Alignment pins (GND)
```

The UART is 115200 baud, 8N1, 3.3 V, no flow control. The I2C pins give direct access to the EEPROM, the PMIC and the GreenPAK, so a GreenPAK can be programmed through them with an
Arduino or similar if its NVM ever has to be rewritten; the bootloader only ever writes the GreenPAK's RAM. The schematics and Gerber files of the board are in <https://github.com/nonarkitten/buffee>.
The Tag-Connect cables have no "click" holes; a hair elastic around the board holds the pogo pins in place for long sessions.
